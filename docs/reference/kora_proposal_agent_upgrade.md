# KORA 产品升级提案：从旅行助手到旅行 Agent

> 来源：Freya · 目标读者 KORA 团队  
> LifeTrip 团队存档，用于对照 `docs/PRODUCT_DESIGN.md` 第十四节。

——从 Conversation 到 Task Completion

## 一、执行摘要

KORA 下一阶段要换一个竞争单位。以前比的是一次对话能回答得多好。接下来要比的是：用户说了一件事，KORA 能不能替他办成。

## 二、KORA 现在在哪

### 2.1 已经验证

- 需求成立：几十万用户、百万级对话
- 场景成立：支付绑定、菜单翻译、地铁打车
- 本地意图成立：裁缝店、牙医、DJI、Pop Mart 等非标召回

### 2.2 下一阶段缺什么

- 没有持续承接用户（记不住人）
- 没有承接任务（知道怎么买但不替用户完成）
- 没有承接变化（暴雨、延误后不继续推进）

## 三、升级后多做了什么（案例）

- **豫园**：从「告诉怎么买」→「票已订好、已加入行程、暴雨自动改期」
- **暴雨**：不是推送天气，而是自动找出受影响活动并重排
- **航班延误**：接机顺延 + 餐厅改约一并处理

## 四、六个连续问题 → 五个产品系统

| 问题 | 系统 |
|---|---|
| 它到底要什么 | **理解** |
| 我需不需要记住 | **记住** |
| 下一步怎么安排 | **规划** |
| 能不能替他做 | **执行** |
| 做完是不是真的成功 | **验证** |
| 中间发生变化怎么办 | **持续推进** |

执行权限 L0–L3：查信息免确认 → 草稿免确认 → 预约要确认 → 支付/取消强制确认。

## 五、五大系统

1. 用户记忆系统
2. 工具执行系统（L0–L3）
3. 行程规划系统（线性时间线，非点状推荐）
4. 主动推进系统（天气、放票、航班…）
5. 质量保障系统（来源标注 + Eval Harness 三层题库）

## 六–十三（摘要）

- 数据：美团、聚合标签、公开 POI；不存原始评论，只存结构化标签
- **核心 KPI：任务完成率**（非对话量、非工具调用成功率）
- **落地 Wedge：门票** → 横向复制 → 执行网络
- 第一个月只验证「帮我订豫园门票」全链路
- 底层能力：Eval Harness + CUA（权限边界先行）

## 十四、给 LifeTrip 的启示（编辑注）

| KORA | LifeTrip 可迁移 |
|---|---|
| 任务完成率 | **走线完成率** / 改线成功率 |
| Wedge = 门票 | Wedge = **一条可走完的 city walk 线** |
| 五大系统 | 同构，但执行权限更低（无支付） |
| 暴雨改行程 | 雨天换室内站 / 缩短路线 |
| Eval 三层题库 | POI 事实题 + 规划决策题 + 安全/闭馆应急题 |
| Memory | 偏好 + 未完成「待走线路」 |
